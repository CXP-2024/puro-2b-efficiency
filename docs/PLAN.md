# 计划

最后更新：2026-11-25

## 1. 问题

Puro-2B 用 22,514 个 RTX 5090 GPU 小时（约 $6.9K）训出 15-benchmark 平均 57.81 分的 2B 模型。
题目要求：**同样的分数，算力少 30%**，即 ≤ 约 15,760 GPU 小时。

全量训练一次需要 96 张 5090 跑一周以上，课程项目无法反复试。
所以整个项目建立在**小模型代理实验**上，最后只在 5090 上做有限的实测验证。

## 2. 基线配方（来自论文与代码仓库）

- 模型：dense decoder-only，Qwen3-1.7B 配置。28 层，hidden 2048，FFN 6144，16 头，序列长 4096，词表 151,936。
- 数据：Phase 1 约 439B token，Phase 2 约 960B token，合计约 1.4T（约 700 token/参数）。
- 优化器：MuonH（Muon + Hyperball）用于注意力和 MLP 矩阵，AdamW 用于其余参数。
- 精度：线性层 blockwise FP8（E4M3），注意力核心保持 BF16。
- 训练策略：Phase 1 → Phase 2（按质量排序的课程学习）→ 常数学习率续训 + 6 个 checkpoint 平均。
- 算力：Phase 1 用 24 张卡，6,009 GPU 小时；Phase 2 用 96 张卡，16,505 GPU 小时。

论文自己指出的弱点：

1. 模型是过训练的（约 700 token/参数），不是算力最优点。
2. Phase 2 扩到 96 张卡后，单卡吞吐从 238 降到 192 TFLOP/s。
3. FP8 下小 hidden size 的算子受内存带宽限制。

## 3. 方向

### 主线：MoE

**假设**：模型处在“数据充足、容量受限”的区间。MoE 在不增加每 token 计算量的前提下增加容量，
所以可以把每 token 激活的参数减少 30% 以上，靠稀疏专家把质量补回来，用更少算力训完同样的 token。

**风险**：

- 专家的小矩阵在 5090 上吞吐会下降，FLOPs 的节省不一定能兑现成 GPU 小时的节省。
- 总参数变多，32 GB 显存放不放得下优化器状态需要实测。
- MoE 与 FP8、MuonH、pipeline 并行的组合没有现成配方。

### 副线：数据配比（RegMix）

论文逐个数据源做筛选，没有做联合配比优化。
用小模型在随机配比上训练，拟合回归模型预测最优配比。代理实验便宜，可以并行。

### 暂不做

- FP4：H100 上无法原型验证；论文已指出 FP8 下算子受内存带宽限制。
- KL-Shampoo：每步更贵，而 MuonH 基线已经很强。
- 纯系统吞吐优化：原作者团队的强项，很难再挤出空间。

## 4. 实验协议

1. 在 H100 上用小模型（0.17B 起）比较**相同 FLOPs 下的验证 loss**。
2. 在 5090 上测各方案的真实吞吐，把 FLOPs 换算成 5090 GPU 小时。
3. 指标：达到同一验证 loss 所需的 5090 GPU 小时之比。
4. 小模型上成立的方案，再放大到 0.6B / 1.7B 检查趋势是否保持。

注意：论文的阶梯实验用的是约 20 token/参数，而正式训练是约 700。
MoE 的收益依赖“容量受限”这个前提，所以代理实验必须在高 token/参数比下做。

## 5. 第一个实验

**E0（基线复现）**：用 Puro-Megatron 在 H100 上训一个 0.17B 的 dense 模型（MuonH，BF16），
得到 loss–FLOPs 曲线。这是之后所有对比的参照，也是 proposal 的 preliminary result。

**E1（MoE 对比）**：把 E0 的每个 MLP 换成 8 个专家（每个宽度为原 MLP 的 1/4），每个 token 走 top-2。
激活的 MLP 宽度减半，总容量翻倍。在相同训练 token 数下比较验证 loss。
放到 2B 规模，这对应每 token 约少 30% 的 FLOPs（MLP 约占 60%，按公开配置估算）。
同时在单张 5090 上测 MoE 层的吞吐。

**E2（数据配比）**：在 E0 的配置上，对数据源配比做随机采样的短程训练，拟合 RegMix 回归。
