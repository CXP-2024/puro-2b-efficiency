# 计划

最后更新：2026-11-25（按 MoE 可行性讨论修订）

## 1. 问题

Puro-2B 用 22,514 个 RTX 5090 GPU 小时（约 $6.9K）训出 15-benchmark 平均 57.81 分的 2B 模型。
题目要求：**同样的分数，算力少 30%**，即 ≤ 约 15,760 GPU 小时。

全量训练一次需要 96 张 5090 跑一周以上，课程项目无法反复试。
所以整个项目建立在**小模型代理实验**上，最后只在 5090 上做有限的实测验证。

## 2. 基线配方（来自论文与代码仓库）

- 模型：dense decoder-only，Qwen3-1.7B 配置。28 层，hidden 2048，FFN 6144，16 头，序列长 4096，词表 151,936。
- 数据：Phase 1 约 439B token，Phase 2 约 960B token，合计约 1.4T（约 700 token/参数）。
- 优化器：MuonH（Muon + Hyperball）用于注意力和 MLP 矩阵，AdamW 用于其余参数。
- 精度：线性层 blockwise FP8（E4M3），注意力核心保持 BF16。
- 训练策略：Phase 1 → Phase 2（按质量排序的课程学习）→ 常数学习率续训 + 6 个 checkpoint 平均。
- 算力：Phase 1 用 24 张卡，6,009 GPU 小时；Phase 2 用 96 张卡，16,505 GPU 小时。

论文自己指出的弱点：

1. 模型是过训练的（约 700 token/参数），不是算力最优点。
2. Phase 2 扩到 96 张卡后，单卡吞吐从 238 降到 192 TFLOP/s。
3. FP8 下小 hidden size 的算子受内存带宽限制。

## 3. 方向

### 主线：MoE

**假设**：模型处在“数据充足、容量受限”的区间。MoE 在不增加每 token 计算量的前提下增加容量，
所以可以大幅减少每 token 激活的参数，靠稀疏专家把质量补回来，用更少算力训完同样的 token。

**设计**：每个 MLP 换成 16 个专家，每个宽度为原 MLP 的 1/8（总容量 2 倍），每个 token 走 top-k。
MLP 约占每 token FLOPs 的 60%（按公开配置估算），所以：

| k | 激活的 MLP 宽度 | 每 token FLOPs 节省 | 净省 30% GPU 小时所需的 MoE 层相对吞吐 |
|---|---|---|---|
| 4 | 1/2 | 约 30% | 100%（没有余量） |
| 3 | 3/8 | 约 38% | ≥ 75% |
| 2 | 1/4 | 约 45% | ≥ 50% |

换算公式：相对耗时 = 0.4 + 0.6 × 激活比例 ÷ MoE 层相对吞吐。

**风险**：

- 专家的小矩阵在 5090 上吞吐会下降，FLOPs 的节省不一定能兑现成 GPU 小时的节省。这是最大的风险，所以吞吐测试排在最前。
- 激活参数更少，质量能否保住没有保证。论文表中 OLMoE（1B 激活 / 7B 总参数）平均分 48.70，低于 Puro-2B；数据和配方不同，不能直接归因，但说明 MoE 不是自动更好。
- 总参数变多，32 GB 显存放不放得下优化器状态需要实测。
- MoE 与 FP8、MuonH、pipeline 并行的组合没有现成配方。Puro-Megatron 里 MoE 的开关和 FLOPs 报告都在，但我们还没实际跑过。

### 保底：缩短 Phase 2 + 数据配比（RegMix）

论文中均匀数据顺序下，Phase 2 的 token 砍一半（$6.9K → $4.4K），15-benchmark 平均分从 55.99 降到约 55.54
（后者由论文表 3、表 4 的分项算出），只差约 0.45 分。
总算力砍 30% 相当于 Phase 2 少约 41% 的 token，所以如果正式配方表现类似，题目约等价于“同样算力下找回 0.3–0.5 分”。

用 RegMix 找这部分：小模型在随机配比上做短程训练，拟合回归模型预测最优配比。
论文是逐个数据源筛选，没有做联合配比优化。

注意：0.3–0.5 分接近评测噪声，验证需要多个种子。

### 暂不做

- FP4：H100 上无法原型验证；论文已指出 FP8 下算子受内存带宽限制。
- KL-Shampoo：每步更贵，而 MuonH 基线已经很强。
- 纯系统吞吐优化：原作者团队的强项，很难再挤出空间。

## 4. 实验协议

1. 在 H100 上用小模型（0.17B 起）比较**相同 FLOPs 下的验证 loss**。
2. 在 5090 上测各方案的真实吞吐，把 FLOPs 换算成 5090 GPU 小时。
3. 指标：达到同一验证 loss 所需的 5090 GPU 小时之比。
4. 小模型上成立的方案，再放大到 0.6B / 1.7B 检查趋势是否保持。

注意：论文的阶梯实验用的是约 20 token/参数，而正式训练是约 700。
MoE 的收益依赖“容量受限”这个前提，所以代理实验必须在高 token/参数比下做。

## 5. 第一个实验

**S1（吞吐测试，不需要训练）**：在 Puro-2B 的尺寸下，单独测 MoE 层（k = 2、3、4）和 dense MLP 的吞吐。
先在 H100 上测相对值，拿到权限后在 5090 上测。结果决定上表中哪个 k 有可能达到 30%。

**E0（基线复现）**：用 Puro-Megatron 在 H100 上训一个 12 层、hidden 768 的 dense 模型（MuonH，BF16），
得到 loss 曲线。这是之后所有对比的参照。

**E1（MoE 对比）**：把 E0 的每个 MLP（宽度 2304）换成 16 个宽度 288 的专家，k = 2、3、4。
相同数据、相同优化器、相同训练 token 数（每参数 ≥ 200 token），比较验证 loss。
要回答的问题：能打平 E0 的最小 k 是多少。

**E2（数据配比）**：在 E0 的配置上，对数据源配比做随机采样的短程训练，拟合 RegMix 回归。
